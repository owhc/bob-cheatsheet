02.5 · Plugins 插件架構（v2.3 核心）
📦 統一打包 Skills + Modes + Rules + MCP
ℹ️
Bob v2.3 支援將整套能力打包進插件目錄，免重啟自動即時監控載入：
.bob/plugins/my-plugin/  # 或 ~/.bob/plugins/
├── mcp.json            # 內嵌 MCP 伺服器
├── skills/             # 專屬技能組
│   └── my-skill/SKILL.md
├── modes/              # 自訂模式定義
└── rules/              # 專屬規則集
  • 即時生效：新增或變更插件免重開 IDE 即刻熱載入
  • MCP 自動綁定：啟用插件時自動載入其 mcp.json
  • 狀態繼承：停用插件會連帶隱藏其所屬 skills/modes
  • 全域插件：放置於 ~/.bob/plugins/ 跨工作區共用
✨ 插件優勢
  • 團隊一鍵分發：Git 同步 .bob/plugins/ 即獲完整工具鏈
  • 隔離與模組化：不同業務領域套件各自獨立維護
  • 乾淨配置：主設定檔免堆積數十個 MCP 與規則

05 · Token 節省策略
核心策略 vs 高成本警示
核心策略
  • 精準任務：明確具體的描述
  • Line Range：只讀需要的行
  • 批次處理：一次完成相關任務
  • 選對工具：apply_diff > write_file
高成本警示
  • 高 讀取 >1000 行大檔案
  • 高 相同檔案重複操作
  • 中 不明確的模糊任務
  • 中 無限制全專案掃描
成本估算參考
操作類型Token 成本建議
簡單查詢100–500直接執行
檔案修改500–2,000apply_diff
複雜重構2,000–10,000分階段處理
全專案分析10,000+精準指定範圍
⚠️
以上僅供參考，依實際使用為主。連接 MCP 會增加基礎成本，只在必要時使用。
06 · v2 全新功能
🤖 Subagents — 平行子代理
ℹ️
讓 Bob 生成獨立代理處理聚焦任務，避免污染主對話上下文。
類型能力適用
explore唯讀、輕量模型搜尋程式碼
general完整工具、預設模型讀寫獨立任務
  • Bob 決定生成子代理 → 你批准 → 子代理執行
  • 子代理有獨立 context window，不共享
  • 任務完成後摘要回傳主對話
💡
vs Subtask：Subagent 靜默執行；Subtask 在 UI 顯示完整對話可追蹤。

ℹ️
每個任務前自動建立快照，底層使用 Shadow Git Repository。
快照時機任務開始時、檔案修改前
兩大功能View diff 比較差異   Rollback 還原
還原選項Restore files：僅還原檔案，保留對話
Restore files & task：還原並刪後續對話（不可逆）
限制僅追蹤 Bob 任務內的變更，.gitignore 排除的不追蹤

在 .bob/agents/ 定義 Markdown persona 檔案，讓 subagent 有固定角色、輸出格式與工具限制。
欄位說明

💡
Persona vs Mode：Mode 控制主任務；Persona 控制 subagent 行為。

🔗 Lifecycle Hooks v2.3 擴充
ℹ️
在 settings.json 定義 Shell 命令或 HTTPS 遠端端點，在關鍵生命週期事件自動觸發。
Hook 事件觸發時機阻擋行為Stdout 處理
SessionStartSession 啟動時✗自動注入為上下文
UserPromptSubmit使用者送出 Prompt 前✓ exit 2 阻擋自動注入為上下文
PreToolUse指定工具執行前✓ exit 2 阻擋忽略
PostToolUse工具完成後✗忽略（接收工具 I/O）
PreCompact v2.3上下文壓縮前✓ exit 2 阻擋檢查或阻擋壓縮
PostCompact v2.3上下文壓縮完成後✗壓縮後處理
PermissionRequest v2.3工具請求授權時✓ 自動解析自動判定授權
PermissionResolved v2.3授權決定成立時✗授權稽核
StopAgent 停止後✗後續清理/通知
 
// settings.json — 支援 command 與 https 雙重 handler
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "^(write_file|apply_diff)$",
      "hooks": [{
        "type": "command",
        "command": "sh .bob/hooks/security-guard.sh",
        "timeout": 5
      }]
    }],
    "PostToolUse": [{
      "hooks": [{
        "type": "https",
        "url": "https://audit.company.internal/bob-events"
      }]
    }]
  }
}
💡
遠端工作區支援：Hooks 現已原生支援 Remote SSH 環境，並在遠端主機上依工作區路徑正常運作。

09 · PR 生成 · Code Review · MCP OAuth
🔀 Pull Request 生成
  • 3 種啟動：Source Control PR 圖示 · 命令面板「Bob: Generate PR」· /create-pr
  • 自動偵測 PR 模板（6 個搜尋位置）
  • 選 base branch → 選 remote → 審閱描述 → 建立 PR → 取得連結
  • 生成後可在 Chat 中反覆修改後再確認
💡
分支名稱愈描述性，生成的 PR 描述愈精準。
🔍 Code Review（/review）
  • /review — 審查本地未提交變更
  • /review <branch> — 比較指定分支
  • /review #123 --issue-coverage — 驗證 GitHub issue 覆蓋
  • 結果顯示在 Bob Findings panel
  • Fix with Bob：一鍵開啟 Chat 解決問題
  • Dismiss：忽略不相關的 finding
💡
Settings → Bob Findings → Review Exclusions：可設 glob pattern 排除測試/生成檔案。
🔐 MCP OAuth 2.1 🆕
  • 支援需要使用者授權的 MCP server（GitHub、Google Drive 等）
  • Bob 自動處理完整 OAuth 流程，包含 token 刷新
  • 只需設定 server URL，無需手動管理 token
  • Settings → MCP → Renew / Reset auth 管理狀態
// .bob/mcp.json — OAuth server
{
  "mcpServers": {
    "my-oauth-server": {
      "url": "https://your-server/mcp"
    }
  }
}

靜態 Authorization header 與 OAuth 二擇一；混用會禁用 OAuth 自動流程。

總原則
🧭 放哪裡
  • 專案根目錄：AGENTS.md 放「為什麼」、.bobignore 放「不能碰什麼」
  • 專案內 .bob/：放可操作的配置（Rules、Commands、Skills、Memory）
  • 全域 ~/.bob/：放跨專案共用設定（個人模式、MCP、常用規則、全域插件）
  • 高成本項：AGENTS.md、custom_modes.yaml、.bob/mcp.json
  • 按需載入項：Slash Commands、Skills、Plugins
🎯 判讀公式
高直接影響系統提示或長期上下文
中規則類檔案，依載入順序生效
低僅在觸發時載入，不會常駐
🗝️
判讀公式：位置決定範圍、檔名決定用途、載入時機決定 token 成本
Canonical Folder Mapping
your-project/                              ← 工作區 / project root
├── AGENTS.md                              ← 團隊原則、開發標準（自動載入）
├── .bobignore                             ← 阻擋敏感檔案/資料夾
├── .gitignore                             ← 常與 .bobignore 搭配
└── .bob/                                  ← 專案級 Bob 設定，優先於全域
    ├── settings.json                      ← 專案設定、Hooks、Profiles
    ├── custom_modes.yaml                  ← 自訂模式；模式指令進系統提示
    ├── mcp.json                           ← 專案 MCP 設定（v2 規範）
    ├── rules/         *.md               ← 所有模式共用；持續影響回應
    ├── rules-{mode-slug}/  *.md          ← 只在該 mode 載入
    ├── commands/      *.md               ← 手動觸發時載入，低成本
    ├── skills/
    │   └── skill-name/
    │       ├── SKILL.md                   ← 技能主定義；選擇時載入
    │       └── support-files...
    ├── plugins/                           ← Plugins 套件打包 🆕 v2.3
    │   └── plugin-name/                   ← 內建 mcp.json, skills, modes, rules
    ├── agents/
    │   └── code-reviewer.md               ← Subagent Persona 定義
    └── memory/                            ← Memory Import 模組庫
        ├── intro/   core/   features/
        ├── security/   best-practices/
        └── project-context.md

~/.bob/                                    ← 全域設定，跨專案共用
├── settings/
│   ├── settings.json
│   └── mcp.json
├── custom_modes.yaml
├── plugins/                               ← 全域插件目錄 🆕
└── rules/  rules-{mode}/  commands/  skills/  agents/
.bob/ 子資料夾用途地圖
路徑主要用途載入時機建議寫法
rules/所有模式共用規則中 對話開始時短、小、單一主題、多檔拆分
rules-{mode}/某一 mode 專用規則中 僅該模式啟用時只寫該 mode 真正需要的限制
commands/Slash Commands低 手動觸發時一個命令只做一件事
skills/複雜任務流程高 被選中時載入SKILL.md 聚焦，支援檔外拆
plugins/ v2.3整合套件（Skills+Modes+Rules+MCP）低 熱載入監控一模組一目錄，內建獨立 mcp.json
agents/Subagent Persona 定義低 spawn 時匹配載入name/description/tools 三欄位
memory/@path 引用的模組化知識由 AGENTS.md 引用時按主題分層，不要堆成大檔
custom_modes.yaml定義角色與 custom instructions高 進系統提示只保留必要 persona
mcp.json v2.3MCP server 註冊與描述（v2）高 description 成本明顯只連必要 MCP，使用 v2 協議
settings.json設定、Hooks 與 Profiles通常不進上下文視為執行設定，包含 hooks 與 profiles

🔄 載入順序 & 實務建議
規則鏈（低 → 高）
  • ① 全域規則 ~/.bob/rules/
  • ② 工作區模式規則 .bob/rules-{mode}/
  • ③ AGENTS.md（專案根目錄）
  • ④ 工作區一般規則 .bob/rules/
按需載入
  • Commands：使用該命令時才載入
  • Skills：被挑選/批准後才載入
  • MCP：連線時 description 進提示
實務建議
  • 長內容放 Memory，不放根 AGENTS
  • 共用規則短、模式規則更短
  • 高成本設定只保留必要項

進階技巧
💡 實戰技巧
  • 從小開始：先建 AGENTS.md + 1–2 Rules
  • 逐步擴展：需要時才加 Commands/Skills
  • 保持簡短：每個檔案專注單一主題
  • 定期審查：移除不再使用的配置
  • 版本控制：配置納入 Git
⚠️ 常見錯誤
  • 過度配置：一開始建立所有機制
  • 內容重複：在多個地方寫相同規則
  • 檔案過大：AGENTS.md > 500 行
  • 缺乏組織：Memory 檔案沒有分類
  • 忽略成本：載入過多不必要內容
🚀 進階應用
  • 多專案共用：全域 Rules 放個人偏好
  • 模式專屬：rules-code/ 只在 Code 模式
  • 動態載入：Skills 按需批准載入
  • 分層管理：Memory 按主題分目錄
  • 版本演進：配置隨專案成長調整
